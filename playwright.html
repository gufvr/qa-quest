Como esta missão funciona

Monte a estrutura, associe locators, ordene ações, componha assertions e compare três perfis. O exemplo exibido é código para um projeto Playwright Test configurado externamente, não um editor executável.

Até 100 XP: estrutura 10, locators 15, ações 15, assertions 20, sincronização 15, diagnóstico 15 e revisão 10. Correção vale metade do item. Pontos fracionários são mantidos na rodada; só o total final é arredondado ao salvar, conforme o progresso atual.

Só a conclusão é salva. Sair ou recarregar reinicia a rodada em andamento, não seu melhor resultado. Evidência incompleta não reduz pontos. Instalar StepScript ou ler o PDF não muda seu XP.

      LINHA DO TEMPO DIDÁTICA · NÃO É UM TRACE REAL

      O que mudou entre a ação e a assertion?

      Perfis locais independentes. Observe estado, instante da leitura, resultado esperado, observado e impacto antes de classificar.

      Inspecionar o trecho frágil

      count captura um número naquele instante. expect(snapshot).toBe não reconsulta a lista. Isso é diferente de await expect(cards).toHaveCount(2). expect.poll com uma função e critério adequados é outra estratégia válida, não a causa da falha deste perfil.

        Isolamento, retries e Trace Viewer no projeto real

        Playwright Test fornece contextos de navegador isolados por teste. Fixtures e beforeEach ajudam a preparar o caso. Projects definem configurações; storageState pode reutilizar estado de autenticação e não garante independência sozinho. Nada disso é configurado nesta simulação. 

        import { defineConfig } from "@playwright/test";
export default defineConfig({
  retries: 1,
  use: { trace: "on-first-retry" },
});

        No projeto real, essa configuração grava o trace na primeira nova tentativa. Retry de um teste inteiro difere do retry de uma assertion. O QA Quest não gera nem recebe trace.zip, gravações ou scripts.
